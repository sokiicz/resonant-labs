What is it?

Countrio is the higher or lower format, but every card is a country. You're shown one country with a number — its population, say — and a second country with the number hidden. Guess whether the next one is higher or lower. Get it right, keep going. Get it wrong, the run ends. Simple loop, hard to put down.

The modes

  • Endless: Population — infinite run, your best streak saves per board.
  • Endless: Area — same loop, but land area in km². Different intuition, different leaderboard.
  • Daily challenge — one shot per day, deterministic deck shared by every player. The mode rotates by day, so today might be population and tomorrow area.

Leaderboards

Two scoreboards per board. This device always works — your local top 10, stored in your browser. 🌐 Global shows the top 10 across every player, auto-refreshes every 15 seconds while open, and highlights your row when you're on it. Off the board? It still tells you "You: #N" so you know how far off you are.

No account, no install

Open the page and play. The whole thing is a static build served from GitHub Pages, so there's nothing to sign up for and nothing to download. Your local scores live in your browser. Your global scores are just a nickname on a leaderboard. That's it.

The idea

Higher-lower games have been around forever and they're still some of the most-played casual games on the web. I wanted one that rewarded a different kind of intuition — geography instead of celebrity follower counts — and that had a daily challenge worth comparing with friends. The whole thing started as a folder called higher-lower-countries. The rename to Countrio came on day two.

Building it

The core loop went up fast: a deck of countries, a deterministic shuffle, a comparison, a streak counter. The interesting design work was the daily challenge — every player on a given day needs to see the exact same sequence of cards, but the seed has to change each day so it doesn't get stale. A simple date-based RNG seed does the job, and the mode (population vs area) rotates by day so the daily doesn't feel one-note.

The global leaderboard was the next puzzle. I didn't want a backend to maintain — no Node server, no database to keep alive — so the browser talks to Upstash Redis directly via REST. Sorted sets handle ranking for free. Each board (hlc:lb:endless-population, hlc:lb:endless-area, hlc:lb:daily:<YYYY-MM-DD>) gets trimmed to the top 100 on every write, and daily boards auto-expire after 14 days. Storage stays small forever.

"The token is in the public bundle. Worst case if it leaks: rotate it in the Upstash console and redeploy. That's an acceptable trade for not running a server."

The mobile pass

Two cards, big tap targets, no chrome. The whole game has to work one-handed on a phone — which means the higher/lower buttons need to be where a thumb naturally lands, the country names need to wrap properly, and the leaderboard needs to feel like a list not a table. That pass took longer than the game logic.

Architecture

One static SPA. No server. The browser POSTs scores and reads top-10 lists straight from Upstash via its REST API. Sorted-set schema:

  • hlc:lb:endless-population — global Endless: Population top 100
  • hlc:lb:endless-area — global Endless: Area top 100
  • hlc:lb:daily:YYYY-MM-DD — per-day daily challenge, expires after 14 days

Every write runs ZREMRANGEBYRANK to trim the board back to the top 100, so storage stays bounded forever. The client validates score range and nickname before each submit. Upstash's free tier rate-limits anything abusive.

The deterministic daily

The daily deck is built from a seeded PRNG. The seed is the date (UTC). Every player who opens the daily on a given day gets the same sequence of countries in the same order. The mode (population vs area) rotates by day too. No coordination needed — pure client-side determinism makes it work.
